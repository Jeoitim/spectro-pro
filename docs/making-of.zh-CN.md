Spectro 最初的目标，是受 [Shadertoy](https://www.shadertoy.com/) 上一些很酷的
WebGL 实验启发，做一个音乐可视化器。当时我刚开始在 Atlassian 做前端开发，上一份
工作主要使用 C#/.NET 做后端，因此想利用这个有趣的项目重新熟悉 Web 技术。几个长
周末和一些工作日晚上之后，Spectro 诞生了。虽然最初的目标没有完全实现，但我仍然
做出了一个自己觉得同样酷、同样有趣的东西。

那么，[Spectro](https://calebj0seph.github.io/spectro/) 到底是什么？标题其实已经
说明了一切：它是一个运行在浏览器中的实时语谱图生成器，可以直接把麦克风或浏览器
暴露的其他输入设备中的声音可视化，也可以从设备上的音频文件生成语谱图，并实时调
整许多控制语谱图外观的参数。

如果你从来没有看过语谱图，它大致是这样的：

![Spectro 生成的一段歌剧语谱图](/docs/spectrogram-example.png?raw=true) \
*Spectro 生成的一段歌剧语谱图*

语谱图本质上是在可视化一段声音中包含的不同频率：时间沿水平方向，频率沿垂直方向，
某个时间点和频率上的能量则用该位置的颜色表示。语谱图的应用范围很广，从地震活动
可视化到机器学习中的语音识别都能用到它；这里我更希望提供一种有趣、直观的声音观
察方式。

## 从时域到频域

我们通常把声音想象成一个随时间变化、上下振荡的波。在计算机中，声音由固定时间间隔
采样得到（通常是 44100 Hz），每个采样点以 -1.0 到 1.0 之间的数字保存，并按时间
顺序排列。播放时，这些数字音频采样会送入 DAC 芯片，由它重建采样所表示的模拟信号。

用这种方式表示的音频属于*时域*：信号按照时间储存。这种表示很容易理解和实现，但当
我们想知道声音中有哪些频率时就不够方便了。此时需要把声音转换到*频域*，可以使用
快速傅里叶变换（FFT）。

FFT 接收时域采样，返回一组复数，描述组成输入信号的不同正弦频率的相位和幅度。换句
话说，它把“随时间变化的信号”转换成“随频率变化的相位和幅度”。这个过程可以反向执
行以重建原始信号；我们也可以先在频域修改音频的一部分，再转换回去，这正是许多数字
信号处理技术的基础。

![FFT 示例](https://akshaysin.github.io/images/mpl-basic-fft.png) \
*对一个包含两个相互重叠正弦频率的信号进行 FFT；下方只显示幅度* \
*图片来源：[@akshaysin](https://github.com/akshaysin)*

FFT 有一个重要特性：输入 *n* 个采样，会得到 *n* 个频率 bin。也就是说，参与计算的
音频越长，频率信息越细。这和量子物理中的海森堡不确定性原理很相似：粒子的位置和动
量不能同时被无限精确地测量，只能更精确地知道其中一个。对于 FFT，也可以把音频切成
很短的片段，以大致知道某个时间点附近的频率；或者使用整段音频，以更高精度知道频率，
但无法知道不同频率具体出现在什么时候。

生成语谱图时，这个特性尤其重要：横轴和纵轴不可能同时拥有最高分辨率。Spectro 将音
频切成每块 4096 个采样（以 44100 Hz 计算约 90 ms），在时间和频率分辨率之间取得一
个我认为适合音乐观察的平衡。4096 个采样可以提供 2048 个垂直频率像素，接近 4K
显示器的高度；90 ms 的时间长度也明显短于大多数音乐音符。

你可能会疑惑：4096 个音频采样为什么只有 2048 个频率分辨率，难道不应该有 4096 个
频率 bin 吗？这是因为输入为实数（音频正是如此）时，FFT 输出的后半部分其实是前半
部分经过 90 度相移后的镜像。这与 FFT 处理复数正弦波有关：当我们只提供描述实数正弦
波的采样时，结果会包含两个相同但相互正交的实数波。既然同一信息出现了两次，我们只
需显示其中 *n / 2* 个频率 bin。[StackExchange 上的这个回答](https://dsp.stackexchange.com/a/4827)
对此有更详细的解释。

## 窗函数（不是操作系统的窗口）

现在我们知道，可以把音频切成小块，对每一块执行 FFT，再获得该块中的频率信息。那这
样就足以绘制语谱图了吗？还不行，我们还没有讨论窗函数。

FFT 假设传入的采样属于一个无限重复的波。你可能听过电脑卡住时把几毫秒声音循环播放的
刺耳噪声：每次循环从最后一个采样突然跳回第一个采样，跳变会制造很高的频率。把一段
音频直接截出来交给 FFT 时，FFT 会把片段首尾相接地理解成无限重复的波，于是频域数据
会被许多原本并不存在的频率污染。

![没有应用窗函数的语谱图](/docs/spectrogram-no-windowing-example.png?raw=true) \
*不使用窗函数时的结果；注意其中大量竖线*

解决办法是使用窗函数。它会让音频片段靠近两端的采样逐渐变小，使片段重复时的连接更
平滑。具体来说，只需把每个音频采样乘以窗函数在对应位置的值；窗函数通常呈钟形。

窗函数能显著减少频域污染（通常称为*旁瓣*），但不能完全消除。不同窗函数对旁瓣的影
响不同；一般来说，旁瓣压得越低，窗就越窄，能用于分析的采样也越少。

![Blackman–Harris 窗](https://upload.wikimedia.org/wikipedia/commons/0/0a/Window_function_and_frequency_response_-_Blackman-Harris.svg) \
*Blackman–Harris 窗函数（左）及其对应 FFT（右）；注意频域中的低旁瓣强度*

Spectro 选择 Blackman–Harris 窗，因为它的旁瓣很低。为了弥补窗函数较窄的问题，Spectro
每隔 1024 个采样，就对一个 4096 采样的窗口执行一次 FFT。这样窗口会重叠，同一个采
样需要参与四次 FFT，但可以让每个采样在最终语谱图中的贡献更均衡。否则，处在片段边
缘的采样会被窗函数压到接近零，几乎不会出现在语谱图中。

## 绘制数据

接下来就是有趣的部分：把加窗后、已经转换到频域的音频显示到屏幕上。在 Spectro 的早
期原型中，我使用普通 canvas，手动把每个 FFT 结果映射成一列颜色，再把颜色写入屏幕
像素。令人意外的是，这种方式相当快：用麦克风作音源时可以轻松达到 60 fps。可能是
因为 FFT 和颜色映射等 CPU 密集型工作都放在了专用 Web Worker 中，但总的来说，性能并
不是大问题。

软件渲染真正的问题出现在需要回看并重新绘制已有语谱图时。例如，放大语谱图、调亮画
面或切换配色，都意味着在 CPU 上重新更新整块屏幕的像素；当屏幕已经充满像素时，这会
变得很慢。

我本可以接受“改变绘制参数需要等待”的限制，但这会让使用体验不够有趣。如果计算机有
什么办法可以同时更新数百万个像素就好了……等等，它们确实有：这正是让 GPU 通过
WebGL 接管繁重绘制工作的好时机。

我的第一项任务，是把原始 FFT 数据（更准确地说，是各频率 bin 的幅度）送到 GPU。由于
Spectro 以滚动方式只显示最近录到的声音，我需要在内存中保留最近 *X* 个 FFT 窗口，
其中 *X* 是 canvas 的宽度，同时还要允许新音频快速写入。这非常适合使用循环队列：它
通过固定大小数组储存数据，并用起点和终点指针记录数据的加入与移除。

每当一个新的音频窗口准备好，就计算它并加入队列，必要时覆盖最旧的数据。WebGL 渲染
器每一帧检查队列，发现新数据后，把它复制到 GPU 上的单通道浮点纹理。纹理最终会与队
列中的 FFT 数据保持一致；每帧只写入新数据，因此更新很快，核心调用是
`texSubImage2D()`。

GPU 开始接收 FFT 数据后，我需要把它映射到屏幕像素。最初先绘制一个全屏矩形，再用一
个简单的片段着色器把 FFT 纹理以黑白方式显示在矩形上。这是一个好的开始，但语谱图会
固定在屏幕上，数据只是在从左到右更新；我想要的效果是屏幕跟随最新音频滚动，最新数
据在右侧，较旧数据在左侧。

为此，我把循环队列的起点和终点指针传给片段着色器，再用它们变换纹理坐标，让起点总是
出现在左侧、终点总是出现在右侧。这个方法有一个限制：变换后可能需要采样纹理的末端
之外。当 x 方向的偏移到达纹理最右边时，需要重新从最左边显示数据。

通常可以把 WebGL 的 `TEXTURE_WRAP_*` 参数设为 `REPEAT`，让它自动重复纹理坐标。但这
只对宽高都是 2 的幂的纹理提供支持，而 FFT 纹理的宽度等于 canvas 宽度，未必是 2 的
幂。

![WebGL 纹理循环的限制](/docs/texture-wrapping.png?raw=true) \
*WebGL 中非 2 的幂纹理的纹理坐标会被限制在边缘*

那时我担心这个效果无法实现，但很快想到着色器中有一个简单的办法：`mod()` 函数。把
纹理坐标变换完之后对 1.0 取模，就能把坐标保持在 0.0 到 1.0 之间，实现循环。这个
方法会失去纹理第一行和最后一行之间的平滑插值，不过语谱图通常以接近原始分辨率观
看，不会放大到极端程度，因此几乎看不出来。

## 增加绘制选项

剩下的工作，就是加入控制语谱图外观的选项。有些选项非常简单，只需要在着色器中对 FFT
数据做一个数学操作，例如用乘法实现灵敏度调整。另一些选项，例如频率刻度和配色，则
需要更多工作。

为了让语谱图能根据不同频率强度显示颜色，而不是只有黑白，我使用了一种常见技术：把
颜色渐变作为一维纹理上传到 GPU。之后，只需在 0.0 到 1.0 的位置采样这张纹理，就能取
得对应颜色。对语谱图来说，采样位置就是某个时间和频率上的 FFT 幅度值。

为了让颜色之间的过渡更平滑，我在渐变色之间使用二次插值，并在 Lab 颜色空间中进行
插值。二次插值增加了过渡的平滑感，Lab 颜色空间则让不同颜色之间的视觉变化更自然。
切换配色时，只需重新生成颜色渐变纹理并上传到 GPU。

![颜色渐变纹理](/docs/color-gradient.png?raw=true) \
*颜色渐变纹理示例：在 Lab 颜色空间中使用二次插值*

频率刻度选项使用了类似的技术，它能让语谱图纵轴上的不同频率看起来更大或更小。Spectro
实现了 *linear* 和 *[Mel](https://en.wikipedia.org/wiki/Mel_scale)* 两种刻度。线性
刻度不改变频率间距；Mel 刻度试图贴近人类对音高的感知，让低频占据更多空间。

实现方法仍然是使用纹理：给定纹理中的一个位置，得到一个值，表示应该从 FFT 数据的哪
个位置采样。线性刻度的这个值从 0.0 到 1.0 线性增加；Mel 刻度则根据 Mel 公式，在开
始处增加得更慢，之后逐渐加快。

![刻度纹理](/docs/scale-gradient.png?raw=true) \
*Mel（上）和线性（下）的刻度纹理*
